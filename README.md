### 这份文档是什么

官方汇总页是索引式记录：每位分享者一段客观描述加若干外链。逐章精读在逐条访问个人主页、产品站点、GitHub 仓库与公开报道之后扩写，每一章包含五段：

1. **身份与场景** — 这个人是谁，在什么位置上做这件事
2. **他讲了什么** — 分享内容的客观还原
3. **关键点分析** — 5–7 条，说明「为什么这样设计」「难点在哪里」
4. **可迁移的方法** — 可以拿去用的具体动作
5. **边界与提醒** — 这个方案的局限、代价、失效条件

四期的公开材料密度不同：第一期多为已上线产品与仓库；第二期多为工作流、现场口述与开发中项目；第三期与第四期在两者之间，设备、科研与安全类章节的可核实页面较多，社交平台入口较难取得。每份文档末尾的事实边界说明会逐条列出哪些内容可以核实、哪些只是现场记录。

### 各期看点

#### 第一期 · 一个人能做出什么东西

- 最好的资源，往往是已经拥有的那个
- 「可编辑」比「能生成」值钱
- 合规与授权成为技术方案的一部分
- 小团队的护城河是细节密度
- 真正的瓶颈从执行转移到判断

#### 第二期 · 怎么组织工作、怎么决定看什么

- 组织单位从会话与产品变成任务、skill 与 MCP
- 筛选权回流个人，同时争取被 AI 选中
- 把隐性判断写成显式结构
- 把最终决定权留在人这一侧
- 门槛从实现侧移到评估侧

#### 第三期 · 怎么让机器先读、把判断交出去

- 信息入口先过机器：AI 先读、先判断
- 苦劳与价值分离，交付形式决定内容的位置
- 一个人的项目靠边界与规则维持
- 老设备、旧文档与本地文件仍有再开发空间
- 身体、注意力与情绪，是自动化覆盖最慢的部分

#### 第四期 · 上下文怎么托管、门槛移到哪一层

- 上下文正在变成可以托管、复用与共享的资产
- 一次证伪比十次证明更省成本
- 门槛移到上架、被看见与被信任
- 设备与本地环境重新提供差异
- 智能可以租用，记忆与判断需要自己持有

### 怎么读

- **只有十分钟**：每期正文的第五部分把当期的分享收敛成 5 条判断。
- **对某个方向有兴趣**：每章可独立阅读，不必按顺序。
- **想找方法**：每章末尾的「可迁移的方法」是压缩过的行动清单。
- **准备做产品**：先看「边界与提醒」，那里写的是别人踩过的坑。
- **想找人**：站点首页有 82 个席位的主页与项目链接索引。

## 编辑标准

- **推断与事实分开写。** 厂商自测、现场口述、社区转述各自标注，不把推断写成事实。
- **每条数字带来源等级与复核日期。** 甲级是直接读官方页面得到的；乙级是从官方文档读到但本次未重复核对；丙级是社区汇总；丁级是本次没有可靠来源。
- **会过期的内容标明截止日期。** 免费额度、星标数、定价都属于这一类，读者按日期判断它还值不值得信。

## 静态站点

[在线阅读](https://73mtq.github.io/public-reading/) 由仓库 `docs/` 目录通过 GitHub Pages 发布（分支 `main` / 目录 `/docs`）。站点提供：

- **首页**：三个栏目（活动精读、学习手册、资源索引）的入口卡片，最新一期按主题跳转，以及 82 个席位的主页加项目链接索引（每张卡片可跳本站精读章节，也可直达外部站点）；
- **章节内**：每章顶部列出该分享者的主页、介绍的项目、源码、幻灯片、样片等链接，取自官方汇总页；官方没给的会如实标注；
- **文章页**：粘性侧栏目录（可按分享者姓名筛选、`Ctrl/⌘ + K` 定位）、章节锚点、阅读进度条、返回顶部、上一期与下一期；
- **移动端**：正文 16–16.5px / 行高 1.85，右下角「目录」悬浮按钮打开带遮罩的抽屉，触摸目标 ≥44px，表格可左右滑动并有提示，尊重 iOS 安全区；支持 `prefers-color-scheme: dark` 与 `prefers-reduced-motion`；
- **资源索引**：需求速查、全站外链总表与 98 个资源页，与其它栏目共用侧栏目录、移动端抽屉与夜间模式；
- **跳转**：全部外部链接在新标签页打开，正文里的裸域名会自动转成可点击链接；地址误带 `**` 等字符时 404 页会自动跳回首页。

本地重建：

```powershell
python -m pip install markdown
python .\refresh_links.py
python .\build_site.py
```

`build_site.py` 读取 `tab-thursday/` 下的四份 Markdown、`handbook/` 下的五份 Markdown 与 `links.json`，生成 `docs/` 下的 HTML、CSS、JS、`404.html` 与 `.nojekyll`。`links.json` 由 `refresh_links.py` 从官方 Markdown 端点抓取并按人结构化（主页 / 项目链接），已随仓库提交，因此构建过程完全离线；官方发布新一期或链接有变动时才需要重跑。

新增期数时改三处：在 `tab-thursday/` 新增精读 Markdown；在 `refresh_links.py` 的 `PAGES` 与 `EXPECTED` 各加一行；在 `build_site.py` 的 `ISSUES` 加一项。新增手册篇目时在 `build_site.py` 的 `GUIDES` 加一项。随后重跑两个脚本并提交。

## 事实边界

这两个栏目对「可信」用的是同一条线：**不把推断写成事实。**

- **厂商自测数据**单独标注。Ego lite 的 398s/587s/605s/615s、1.64/2.43/2.66 美元，对照组配置未公开，只能作为方向性参考。
- **未完成验证的方案**已注明。iPhone Use Pro 只在作者本机（Apple Silicon + macOS 27.0.1 + iPhone 16 Pro）实测通过，仓库原文写着「不要把本机验证当成其他机器验证」。
- **公开材料不足的分享者**，对应章节改为「以主题为锚点 + 行业通行框架」的方法论推演，凡属推断均在文中标明。
- 即刻、小红书、X 与 LinkedIn 短链在未登录状态下常无法取得完整内容，部分分享者的完整内容可能未被覆盖。
- 各期的完整核查记录见对应文档末尾的「附：事实边界说明」。
- **学习手册的免费额度与定价**复核于 2026-09-28，两个月后可能已经变化；文中标为丁级的条目在核对时就无法回源，使用前必须自行确认。
- **高校 AI 规范**引用的是 2024–2026 年公开发布的文本，条款可能修订，以学校官网最新版本为准。
